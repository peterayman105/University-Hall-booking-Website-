# Fix P3019 (SQLite → PostgreSQL)

Error means: `schema.prisma` says **postgresql** but `migration_lock.toml` or old migrations still say **sqlite**.

## Fix (copy-paste in PowerShell)

```powershell
cd "c:\Users\peter\OneDrive\Desktop\WAGRAD\findyourspot"

# 1) Remove ALL old SQLite migration folders (keep only the postgres one)
Remove-Item -Recurse -Force "prisma\migrations\20260406173011_init" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "prisma\migrations\20260410120000_user_photo" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "prisma\migrations\20260416100000_hall_images" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "prisma\migrations\20260416103000_booking_review_reject_reason" -ErrorAction SilentlyContinue
Remove-Item -Recurse -Force "prisma\migrations\20260416110000_hall_extras" -ErrorAction SilentlyContinue

# 2) Fix lock file (must say postgresql)
@'
# Please do not edit this file manually
# It should be added in your version-control system (i.e. Git)
provider = "postgresql"
'@ | Set-Content "prisma\migrations\migration_lock.toml" -Encoding UTF8

# 3) Confirm .env has Neon URL (not file:./dev.db)
# DATABASE_URL="postgresql://....neon....?sslmode=require"

# 4) Deploy to Neon
npx prisma migrate deploy
npx prisma generate
npm run db:seed
```

You should see **1 migration** found, not 5.

## If migrate deploy still fails — use db push (quick bypass)

On a **fresh empty** Neon database:

```powershell
npx prisma db push
npx prisma generate
npm run db:seed
```

This creates tables without using old migration history.

## If Neon already has broken partial tables

Neon dashboard → **Reset branch** (or new project) → new connection string → update `.env` → run commands again.
